# 二维码与外部标签（preview.7）

## 新增及编辑设备

“二维码与标签”分成两部分：

| 项目 | 来源与用途 |
|---|---|
| 系统二维码及只读链接 | 保存设备后，按“扫码访问设置”的统一地址与设备稳定 ID 生成，无需手工填写。编辑设备时可查看和打印。 |
| 外部二维码内容 | 已有厂商/旧系统标签实际包含的编码，选填。例如 QR-2026-001。 |
| 二维码链接（外部原地址） | 已有标签实际包含的完整链接，选填。例如 https://vendor.example/qr/001。不是本平台统一访问地址。 |

两项外部信息可只填写一项，或分别绑定同一设备的不同标签。不能仅凭“QR-2026-001”推测外部 URL，两项不自动拼接或互相覆盖。可点击“扫描已有标签”，打开页面摄像头录入：HTTP/HTTPS 内容填入外部链接，其他内容填入外部编码。内容受原字段 500/255 字符限制，需保存设备后生效。摄像头需要受信任的 HTTPS。

打印系统标签时重新读取已保存的设备，避免打印未保存的名称、编号等编辑内容。系统统一地址仍在“系统设置 → 扫码访问设置”管理；外部标签不会替换它。

## 查询与盘点

在本平台的扫码查询或盘点页面扫描已有外部标签，可定位绑定设备；查询同时保留系统二维码、设备编号、资产编号和 SN 的识别能力。

外部编码/链接按去除首尾空白后的原始内容精确匹配，保留大小写、路径和查询参数，不访问外部网站，也不自动改写厂商链接。设备编号、资产编号和 SN 延续不区分大小写的查询方式。

手机系统相机直接扫描外部 URL 仍会打开原网站，本平台不能改写已贴二维码的内容或接管厂商域名。需要直接进入本平台时，打印系统二维码，或先从平台入口进入扫码页面后再扫描原标签。

同一个识别内容匹配多台设备/备件时提示核查，不自动选择第一条记录；本版不对历史外部标签数据增加全局唯一约束或自动清理重复绑定。

盘点按任务创建时的设备快照识别外部绑定；快照中原本已有的绑定也可识别。任务创建后才新增或更改的绑定不会静默改写历史快照，可在已有任务使用系统码、编号或 SN，或按新的绑定创建后续盘点任务。盘点确认、权限、差异复核流程保持原有行为。

## 数据兼容与部署

沿用 externalQrCode / externalQrCodeUrl 原字段，Excel 导入导出的列名保留。历史填写内容会直接参与后续查询匹配，无需重新导入；本轮不修改数据库结构。

升级前备份并复制原正常运行目录的 .env，执行新包 bash install.sh；保留原项目名、数据库密码、JWT_SECRET 和数据卷。

## 验证范围

专项测试覆盖系统码预览、已保存记录打印、扫描录入分流、外部链接及编码的查询和快照匹配、URL 大小写、空值、损坏快照和重复绑定歧义。前端完整类型检查、测试与生产构建需通过；界面预览使用虚构数据。真实手机摄像头、Docker 启动与生产网络仍需实机验收。
