# 双渠道审批与备件布局（preview.15）

后续 preview.16 已将规格与预警迁入辅助设置，录入可选初始状态，详见《备件工作台使用说明》。以下为 preview.15 行为说明。

## 审批通知

用户已确认原审批邮件最终收到，本次不把“SMTP 已接收”判定为投递故障。增加审批企业微信通知及独立测试和追踪，便于两种渠道同时使用。

1. 在“系统管理 → 告警通知”保存 SMTP 和企业微信机器人配置，启用对应主渠道。
2. 在“系统管理 → 审批规则 → 审批通知”分别启用邮件和企业微信。两种渠道可以同时开启，也可以只开启其中一种。邮件填写独立的 1–20 个管理员收件邮箱；企微复用原告警机器人，发往同一个群。
3. 填写管理员可访问的系统根地址并保存，再点击“测试审批邮件”或“测试审批企微”。测试使用保存后的配置，每渠道每分钟最多一次，与普通渠道测试共享频率限制；测试不会创建或处理真实审批申请，也不会标记真实申请已通知。
4. 在“系统管理 → 通知发送记录”查看结果。同一申请可以有邮件和企微两条记录。新审批邮件记录保存实际收件邮箱和 Message-ID；历史记录不回填。SMTP 已接收不代表投递到收件箱，可凭编号查询邮件服务器轨迹。

后台约每分钟检查待审批申请。每个渠道独立扫描、使用独立锁并发处理、按申请与渠道去重。成功的渠道不常规重发；失败渠道约 15 分钟后重试，不影响另一渠道。已处理申请停止后续扫描，已经在发送中的消息可能仍到达。远端已接收但数据库提交失败时可能重复，不能承诺严格只发送一次。

新增企微审批开关默认关闭，保留原邮件开关和收件人。升级后需在审批规则中启用企微；启用时也会扫描尚未处理、但只发过邮件的申请。用户账号和权限不变，通知链接仍需管理员登录审批。

## 备件日常流程（简化后）

| 要做什么 | 从哪里操作 | 库存如何变化 |
|---|---|---|
| 首次录入或新一批到货 | 机房备件 → 入库登记 | 选择已有型号或填写首次登记资料，一次保存自动建档、增加可用库存并记入库流水 |
| 同一数量库存补货 | 当前记录 → 入库 | 增加当前行可用数量；已有 SN 单件不提供重复入库 |
| 查看库存 | 库存台账、区域统计 | 看可用、预留、在途、维修/故障，按区域、类型及状态筛选 |
| 调出备件 | 当前记录 → 调拨 | 选择目标位置、数量及原因；调出数量转为在途，不计入可用库存 |
| 收到调拨备件 | 在途记录 → 确认收货 | 按本批全部数量收货，转为目标位置可用库存 |
| 领用/安装/故障/维修/报废 | 当前记录 → 更多 | 按原受控状态流转，自动记录流水；故障、维修、报废等覆盖本条库存整批数量并在界面提示 |
| 看操作历史 | 当前记录 → 流水 | 只看这条库存的流转记录，可切换查看全部并导出 |

例如无序列号物料：上海入库 10 件，调拨 3 件到杭州后，上海可用 7 件、杭州在途 3 件；杭州确认收货后，可用变为 3 件，在途归零。按 SN 管理的部件每个序列号对应 1 件；序列号调拨发出时保留原位置作为来源，目标位置在详情和收货提示中展示，收货后再更新位置。

主表按“区域、类型、名称、型号、数量、序列号、备注、状态”展示。区域引用现有资产位置并显示具体存放位置，避免同城库房混淆。规格、料号/管理编码、库位、批次、管理方式、安装设备、保修截止及调拨目标放在展开详情中。资料和预警作为辅助页签，不再要求日常用户先理解规格、空档和办理的关系。

“入库登记”在同一数据库事务中调用原建档和入库逻辑；流水写入失败时整笔回滚，不留下孤立零库存档案。提交编号保证网络重试不会重复入库；同一编号内容不符则拒绝。首次登记自动生成 AUTO-SPARE 管理编码，不假造厂商料号；相同类型、名称、型号和管理方式复用其自动资料，详细规格可在备件资料中补充。需要区分其他接口或料号时，使用明确的已有型号资料。

入库后为可用状态；数量、状态通过操作流转，档案编辑不能直接改账。备注可编辑、清空、搜索、导出和备份，调拨数量批次携带备注。历史资料、盘点、二维码、最低库存和原接口保留，旧零库存档案仍可入库或在无历史时删除。多次入库按记录保留，区域统计查看合计。

## 导航归类

| 分组 | 入口 |
|---|---|
| 工作台 | 运行概览、提醒中心、审批中心 |
| 资产管理 | 终端台账、机房备件、配置与保修中心、扫码盘点、扫码查询 |
| 机房资源 | 区域与机房、机柜管理、机房设备台账、机房大屏 |
| 基础资料 | 区域与资产位置、机柜模板 |
| 系统管理 | 资产操作记录、数据导出与备份、通知发送记录、告警通知、审批规则、扫码访问设置、账号与认证 |

每项入口仍按原角色显示。资产管理员/审计员在系统管理中仅看到原本有权限的资产操作记录和业务导出，审批、账号及通知设置仍限系统管理员。原页面 URL 与旧链接跳转不变。

## 升级与验证边界

新增审批企微开关、通知记录收件人/Message-ID、备件备注字段，由现有启动 AutoMigrate 创建。原数据不清空，默认不新增任何真实外部发送行为。升级沿用旧有效 `.env`、JWT_SECRET 和数据卷，并先备份。

自动回归使用模拟数据库、模拟邮件/HTTP，不代表真实邮件或企微投递。未完成真实 Docker/PostgreSQL 升级和浏览器视觉验收，Android APK 未重打。
