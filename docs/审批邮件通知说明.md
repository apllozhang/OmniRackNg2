# 审批邮件通知

版本：0.2.0-preview.15。

## 配置步骤

1. 管理员进入“系统管理 → 告警通知”，启用邮件，填写 SMTP 主机、端口、加密方式、发件邮箱和认证凭据并保存。现有告警收件邮箱仍只用于告警；审批通知使用下一步单独设置的邮箱。
2. 进入“系统管理 → 审批规则 → 审批通知”，启用新申请邮件通知，填写 1–20 个管理员收件邮箱（每行一个，也支持逗号、分号分隔）。
3. 填写管理员实际可访问的系统根地址，例如 `https://it.example.com` 或 `http://10.0.0.10:15173`。不带 `/admin`、其他路径或参数。该地址仅用于邮件链接，不修改 DNS、端口、证书或网络配置。
4. 保存通知设置。收到邮件后点击链接，用有系统管理员权限的账号登录，即可进入待审批列表进行通过或驳回。审批权限、U 位冲突及版本校验继续由系统执行。

## 发送行为

- 服务启动后检查，之后约每分钟检查一次待审批申请；一次最多处理 20 项。积压多或邮件服务器较慢时会延后。
- 启用后也会通知当前尚未处理的申请，不只通知新创建的申请。
- 每个申请成功通知一次；修改收件邮箱不会重发已成功通知的旧申请。发送失败保留记录，约 15 分钟后重试；已被处理的申请不再进入重试。
- 邮件包含申请编号、设备名/编码/SN、申请账号 ID、上架/迁移的目标机柜 ID/U 位或下架的原机柜 ID/U 位、申请原因、时间和待审批列表入口。
- 邮件仅通知，不包含免登录审批令牌；邮件转发不会授予审批权限。管理员需在系统内审批，邮件发送失败不影响申请本身。
- 在“系统管理 → 通知发送记录”查看结果，摘要以“待审批”开头，可按申请编号核对。失败详情不回显 SMTP 密码。
- 邮件服务器已接受但进程或数据库提交失败时可能重试，因此不能保证任何故障下绝对不重复。

## 配置与升级

审批通知默认关闭。配置保存至现有数据库，SMTP 凭据沿用现有加密存储。两处设置共享版本保护；在其他页面修改 SMTP 后，审批通知页面需“重新加载”再保存。停用 SMTP 前先关闭审批邮件通知。

升级沿用旧目录 `.env` 与原数据卷。新增字段由服务启动时的现有迁移流程创建，不需重新初始化数据库。先备份并在测试环境验证升级。

本次验证使用模拟数据库和假邮件发送器；本机未运行 Docker/PostgreSQL，未向真实邮箱发送邮件。实际升级迁移、SMTP 认证/投递及邮件客户端跳转需在测试服务器验收。

本版也支持企业微信审批通知，可与邮件同时开启，独立去重和失败重试；配置及测试详见《双渠道审批与备件布局说明》。
