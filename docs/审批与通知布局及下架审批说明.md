# 审批与通知布局及下架审批（preview.14）

## 入口分工

| 位置 | 功能 | 说明 |
|---|---|---|
| 工作台 → 审批中心 | 审批待办及历史 | 按状态查看上架、迁移、下架申请，展示申请原因、位置、审批意见，支持通过/驳回 |
| 系统设置 → 审批规则 | 单级审批策略、审批邮件通知 | 独立设置上架、迁移、下架是否需要审批，以及管理员收件邮箱 |
| 数据与审计 → 通知发送记录 | 告警、审批邮件、测试发送记录 | 展示时间、渠道、来源、摘要、发送结果和失败原因，支持服务端分页 |
| 系统设置 → 告警通知 | SMTP、企微、告警规则 | 只维护发送渠道和告警规则，发送记录迁出 |
| 系统设置 → 账号与认证 | 用户、角色、LDAP | 审批处理及规则迁出，不再混入账号认证页面 |

上述审批和发送记录入口均沿用系统管理员权限，未向普通账号或资产审计员开放。公共资产操作审计仍保持原权限。当前审批执行支持系统管理员；规则页面按实际能力展示，不提供无效的其他审批角色选项。

旧 `/admin?tab=approval` 自动跳转审批中心。新审批邮件链接直接进入 `/approvals`，旧邮件仍可使用，登录及管理员权限校验保持生效。旧 `/notification-settings?tab=history` 跳转发送记录。

## 下架审批修复

原下架服务直接移除位置与 U 位占用，没有查询审批策略。本版将下架接入统一位置变更申请及审批事务。

- 增加 `decommissionApprovalEnabled`，默认开启。首次安装及旧数据库新增此字段时均为开启；管理员可在审批规则明确关闭。
- 开启时，所有账号提交下架只创建待审批申请及申请审计，保留原位置、U 位占用、设备状态和正式下架履历。
- 批准时在事务中校验申请版本、待审批状态、设备版本及原位置快照，再删除位置/占用、更新设备为已下架、刷新机柜状态并写履历和审计，最后更新审批结果。任一步失败回滚。
- 驳回不修改设备位置和生命周期。已经处理过的申请不可重复批准。
- 设备已被修改、迁移或下架时，旧申请批准会失败；刷新后根据实际情况重新申请。
- 关闭规则时新下架请求直接执行；已有待审批申请仍需批准或驳回。
- 设备台账和机房大屏根据实际返回显示“下架申请已提交”或“设备已下架”，不误报执行成功。
- 开启下架审批时，机柜图导入若包含直接下架或替换移除原设备，将整批拒绝，并提示从设备台账提交申请。选择忽略移除项可保留原设备；本版没有增加批量审批功能。
- 兼容旧策略客户端：更新请求未带新开关时保留原值，只有显式传入布尔值时修改；保存 false 使用版本条件更新，不受默认 true 影响。

## 通知与部署

审批邮件沿用原 SMTP 和独立收件邮箱。下架邮件明确标记原机柜及原 U 位，提醒管理员审批；邮件本身不执行审批。发送记录的“通道已接收”不等于收件人已收到或阅读。

本次新增 `operation_policies.decommission_approval_enabled` 布尔列，使用现有启动 AutoMigrate，默认 true。其他数据不迁移、不清空，原上架/迁移开关保留。升级先备份，并沿用原有效安装目录 `.env` 和数据库卷；不要重新生成数据库密码或 JWT_SECRET。

本机使用模拟数据库、状态存储和模拟邮件完成回归，未做真实 PostgreSQL 迁移、Docker 升级、SMTP/企微投递和浏览器视觉验收。Android APK 未重新打包。
