## 本轮新增

1. PC 类型；资产位置可为办公区、机房或备件库，机房位置关联原 Room ID。
2. 资产配置扩展：使用人/运维责任人、部门、工位、CPU、内存 GB、硬盘明细、系统、显卡、RAID、端口、环境和重要程度。
3. 原厂保修与第三方维保记录；同时读取原有 warrantyExpiresAt，按上海自然日计算保障状态，最后一天仍在保。
4. 保修、备件保修、U 位容量、最低可用库存和缺失 SN 提醒；启动后及每 15 分钟检查，同类风险更新原记录，处理说明不改变真实状态。
5. 按件/SN 与数量两种备件；零库存建档后入库，出库、预留、安装、拆回、检测、送修、调拨、收货、报废和库存流水。
6. 按件安装关联原设备；库存归零且状态为已安装，关联部件在资产配置页展示。拆回必须确认当前设备位置，进入待检测。
7. 数量调拨生成在途批次，按件调拨沿用同一 SN；收货后才计入目标位置可用库存。
8. 分机房及规格汇总、最低库存规则、标签批量打印（浏览器可保存 PDF）。
9. 盘点任务快照、指定执行人、摄像头/扫码枪/手工核对、重复扫描防重、配置未核验标识、差异双人复核和范围外发现记录。
10. 结案再次检查设备版本；扫码后变更不能静默通过。数量备件的盘点调整生成独立流水。
11. 配置台账、备件、分机房统计、流水、盘点 Excel；完整业务 JSON 包含配置、维保、库存、流水、规则、盘点和提醒，不包含用户密码、LDAP 配置或 JWT。
12. 完整 PostgreSQL 与部署配置加密备份脚本；默认只校验的恢复入口、安全路径及摘要校验。

全部功能不引入金额、净值、折旧、维修费用或其他资金字段。

## 使用顺序

1. 在原系统建立资源树和设备，或通过原 Excel 模板导入；PC 选择新增的 PC 类型，无需上架。
2. 在“资产运营与保修 → 区域与资产位置”建立位置；每个机房建议建立一个明确资产位置，备件柜/层位/料盒填入备件库位。
3. 为未上架设备、PC 补充位置和资产配置；已上架设备优先读取原机柜位置。
4. 登记服务保障，在提醒中心检查到期情况。
5. 在机房备件创建规格、建立零库存档案，再执行入库；关键备件记录具体 SN。
6. 为盘点任务选择位置和执行人，下载/打印标签；先扫码核对，再由另一名授权人员复核差异。

二维码只含应用地址和稳定设备/备件 ID。扫码成功表示识别标签，仍需核实实物和 SN，不代表已验证硬件配置。
手机扫码需授权网络可达、受信任 HTTPS 和摄像头权限。机房无网络时使用授权终端和扫码枪；本版不提供离线模式。

## 权限与当前边界

新增角色 asset_manager、asset_auditor，可由原系统管理页面分配。
扩展接口每次读取数据库当前角色和启用状态；管理员/资产管理员可维护，资产审计员可读及导出，普通用户不能访问新增运营接口。

原受保护资源接口也增加本地账号启用状态与当前角色复验，新增资产审计员不能通过旧接口写入。普通用户原有业务能力保持不变。
重要限制：新增角色不是全系统的区域隔离能力，也不等于员工仅看本人资产。生产采用分区域隔离或员工自助前，必须进一步统一治理原接口的数据范围和员工权限。

保留原 LDAP 实现；启用、组映射、证书策略和目录停用后的既有 JWT 行为需要按企业环境核查，不能据此声称已完成单点登录或实时停用。
备件报废当前由有资产管理权限人员执行并填写处置依据，尚无独立报废双人审批单。原机柜审批继续使用原功能。
办公资产使用状态调整有审计记录，但未新增独立员工领用申请、多级审批、维修工单或附件上传模块。
内存/硬盘配置支持文字明细与带 SN 的实际部件关联；不含每条未编号内存的独立结构化插槽表或自动采集。
SN 保留原设备模型的普通索引，不对存量数据强行加唯一约束；扫描命中多条时要求人工核查。备件非空 SN 使用唯一索引。
继承原系统设备总量 3000 台、单机柜 20 台的业务上限；未在本轮擅自调整。

## 部署与迁移

不要把预览版直接覆盖原生产目录或连接原生产库。先部署到独立测试实例，恢复一份经过授权的脱敏副本验证。

```bash
cp .env.asset.example .env
# 编辑 .env，替换数据库、JWT 和管理员口令中的占位内容。
export COMPOSE_FILE=compose.assets.yml
export COMPOSE_PROJECT_NAME=cabinet-assets-preview
docker compose build
docker compose up -d
docker compose logs --tail=100 backend
```

本轮提供独立 compose.assets.yml，没有固定容器名称、不发布数据库端口，避免与原部署冲突。默认只在本机 15173 端口开放页面。
办公区手机通过企业受控 HTTPS 反向代理访问。原来的 docker-compose.yml 与部署脚本继续保留，不能与新实例共用原生产数据卷。

新表通过现有 repository.Migrate 的 AutoMigrate 路径创建，并新增 PC 类型与资产角色种子。原系统启动也会重建 U 位约束，因此升级应安排维护窗口并先备份。
升级前比较结构、在副本执行迁移、核对所有旧设备/位置/审批/LDAP 记录数量并完成回归。数据库新增表后，回滚程序不等于回滚数据库，须保留版本匹配的完整备份。

## 备份与恢复

Linux 部署主机需要 Docker Compose、GnuPG、Python 3.9+、GNU tar、flock、sha256sum。
口令通过独立的权限 600/400 文件提供，不放进命令参数、不写入源码或备份包。

```bash
export COMPOSE_FILE=compose.assets.yml
export COMPOSE_PROJECT_NAME=cabinet-assets-preview
export BACKUP_PASSPHRASE_FILE=/secure/offline-managed/cabinet-backup.pass
export BACKUP_DIR=/secure/backups/cabinet
bash scripts/backup-assets.sh
bash scripts/restore-assets.sh /secure/backups/cabinet/backup.tar.gpg --verify-only
```

备份会停止此前运行中的 backend/frontend，执行 pg_dump，打包数据库、.env、Compose、版本信息及存在的宿主机 files 目录，GPG 加密后恢复原服务状态。
这会产生维护中断，建议每日低峰执行，并复制到独立存储；单日备份可能损失近一天的新数据。此脚本不提供时间点恢复和高可用。
完整备份含数据库里的 LDAP 绑定配置及 .env 的 JWT/数据库口令，必须限制访问并独立保管解密口令。

恢复演练先在同版本隔离实例执行：

```bash
# 此命令会覆盖目标实例数据库，只能由运维明确选择目标后执行。
bash scripts/restore-assets.sh /secure/backups/cabinet/backup.tar.gpg --restore --confirm-overwrite
```

恢复时应用停止；pg_restore 使用单事务。失败时保持停机，不开放部分恢复数据。
脚本不自动覆盖目标 .env，以免把备份中的旧数据库地址写到新环境。需要完整取出配置时，在受限空目录手工运行 GPG 解密及 verify-backup-archive.py unpack，核查 config/.env 和版本后恢复相匹配配置。
若备份含 files 且目标已存在 files，脚本会要求人工核对而不覆盖，应用继续保持停止。
核对设备数量、SN、机柜位置、库存和流水、盘点快照、角色与 LDAP；登录、导出、扫码和标签回读通过后手工启动 frontend/backend。
备份口令丢失无法解密；应验证密钥托管。企业 LDAP 目录本身不在本应用备份范围内。

## 本地开发与只读页面预览

正常开发使用 Go 1.24、PostgreSQL 16、Node 22+，前端依赖以本次 package-lock.json 和 npm ci 为准；保留的原 pnpm 锁文件不作为本版新依赖的安装依据。

```bash
cd backend && go test ./...
cd ../frontend && npm ci && npm run typecheck && npm test && npm run build
```

需要只评判页面时，先完成前端生产构建，再分别运行：

```bash
node scripts/qa-api.mjs
node scripts/qa-preview.mjs
```

打开 http://127.0.0.1:5175/asset-operations ，预览账号 preview / preview。这些只是虚构界面数据，保存操作会被拒绝；测试服务只监听本机，不用于实际业务或生产部署。

## 验收清单

- 原资源树、大屏、U 位冲突、PDU、导入回导和 LDAP 页面回归通过。
- PC 不占机柜即可登记位置，配置与原设备身份一致。
- 单件备件入库、调拨、收货、安装、拆回和处置能沿 SN 查清；数量调拨总量守恒。
- 重复提交不重复扣减；库存不足、版本冲突、审计写入失败时业务回滚。
- 保修自然日边界、原厂和第三方覆盖、提醒去重及报废停止提醒正确。
- 盘点重复扫码、未核验配置、范围外发现、差异复核和结案后变更检查正确。
- 真实手机 HTTPS、浏览器权限、弱网重试与扫码枪实测。
- GPG 加解密、PostgreSQL 导出导入、配置匹配、文件回读及独立存储恢复演练通过。
