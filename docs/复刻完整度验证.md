# 复刻完整度与 REA 验证

本项目以自有原包 `cabinet-it-assets 0.2.0-preview.16` 的完整源码为基础。完整度分为源码文件保留、静态结构、可构建性和实际业务行为，分别记录，不能用路由数量推算全部业务正确率。

原包 SHA-256：`31e73a24ae54775be155ec4fe0ed57392d014b401ac39c6400ba5a4ef0260db7`。校验锚点与原包一同提供，并非外部发行签名。

## 工具与准备

- Go 1.24.13；本轮验证使用该版本。Dockerfile 默认同版本。
- Node 24.22.1 和 npm；Dockerfile 默认同版本。
- [morluto/rea](https://github.com/morluto/rea) 的官方 npm 包 `rea-agents@6.8.0`，依赖锁位于 `tools/rea/package-lock.json`。
- 如运行真实集成回归：本机 PostgreSQL 16 的 `initdb`、`pg_ctl` 和 `btree_gist` 扩展；Playwright Chromium。

```bash
cd frontend
npm ci
npx playwright install chromium
cd ..
npm ci --prefix tools/rea
```

REA 使用 CLI 即可，不需要修改代理配置或重启 Codex。Go build-info 分析和 JavaScript 静态分析均不需要 Hopper/Ghidra。官方依据见 REA 仓库 README 的 Go binaries、JavaScript/Electron 与 CLI 部分。

## 复跑

在项目根目录执行，`artifacts/` 下每次使用新的目录以保留旧证据：

```bash
python3 scripts/verify-replica.py \
  --original ../cabinet-it-assets-0.2.0-preview.16.zip \
  --output artifacts/verification-001 \
  --rea tools/rea/node_modules/rea-agents/scripts/rea.mjs
```

可通过 `--go /absolute/path/to/go`、`--node /absolute/path/to/node` 指定工具。验证脚本记录真实版本，并将指定 Node 放在子进程 PATH 前。当前应使用上面的工具版本；更换编译器或依赖后应重新建立比对基线。

增加 `--pg-bin /absolute/path/to/postgresql/bin` 会构建本机可执行后端，启动**新建、临时、仅 loopback 的 PostgreSQL**，运行真实 HTTP 回归及浏览器页面验证，最后关闭并清理该测试数据库。测试不接受远程 URL、现有数据库或生产凭据，用户名和口令仅用于本次临时集群。

直接运行真实回归：

```bash
(cd backend && go build -trimpath -buildvcs=false -o /tmp/omnirack-local-server ./cmd/server)
python3 scripts/integration-replica.py \
  --pg-bin /absolute/path/to/postgresql/bin \
  --server /tmp/omnirack-local-server \
  --output artifacts/integration-001 --browser
```

## 输出与解释

- `source-manifest.json`：源码路径与逐文件 SHA-256、整体规范摘要。排除 `.env`、备份秘密、依赖、编译产物、缓存和 `artifacts/`；保留 docs、产品图片、迁移、测试及 API 文档。
- `source-comparison.json`：原包的每个源文件是否仍存在、相同、修改，明确列出排除项。缺失即失败；文件存在不等于实现语义相同。
- `api-routes.json`：实际调用 Gin 路由注册函数，枚举全部 122 条 method/path，不连接数据库、不启动任务。比 grep 单个路由文件更完整；本轮没有新增业务 HTTP 接口。
- `original-go.json.gz` / `replica-go.json.gz`：REA 完整 Go build-info Evidence；编译器、module、依赖和 flags 可复核。
- `backend-function-comparison.json`：使用 Go 自带符号工具补充比较原包与复刻 ELF 的应用函数名，将旧模块前缀规范为新前缀。编译器内联和包装函数变化可能改变符号集合，不以符号相同宣称函数体等价。
- `original-js.json.gz` / `replica-js.json.gz`：REA 完整 JavaScript Evidence，包含 coverage、unknowns 和限制；不是手工改写的结论。
- `*-selection.json`：明确记录选择解析的应用 JS。第三方 `vue-core`、`element-plus`、`http-client`、`vendor`、`spreadsheet` 块保留文件/摘要清单，不运行昂贵语义解析；它们属于显式未知范围。初次全量分析遇到 spreadsheet 单文件超时，故采用应用代码选择，而非隐藏失败。
- `frontend-route-comparison.json`：原包与重建前端的 REA 页面候选路由差异。`/terminal-assets` 别名另由浏览器验证；静态路由候选不代表完整功能验收。
- 测试日志：前端单元/组件、Go 测试、部署脚本与源码摘要回归；可选 `integration/result.json` 和 Playwright 报告。
- `build-manifest.json`：源摘要、工具版本、产物 SHA-256；Linux amd64 Go 产物同参数重复构建须字节一致。

后端支持 `omnirack-server --build-info`，在连接数据库之前输出注入的源摘要。前端提供构建生成的 `build-info.json`。开发构建的摘要明确为 `development`；摘要是可核对元数据，不是第三方签名。根部署脚本自动计算并传递 `SOURCE_SHA256`。Docker runtime 基础层尚未全部锁定 digest，主机重复构建结果不能直接当作 Docker 镜像可复现证明。

## 打包与部署

验证通过且源码未再变动时：

```bash
python3 scripts/package-replica.py artifacts/verification-001
```

生成完整源码包（含 docs 和产品截图）、前端 dist 包及 `SHA256SUMS.txt`。源码有任何变化都必须重新验证后才能打包。原包的预编译后端和 dist 不混入复刻源码包。

根 `deploy.sh` 默认复用本机缓存/镜像源提供的基础镜像，以适配 NAS；需强制拉取时使用 `PULL_BASE_IMAGES=true bash deploy.sh`。数据库和既有 `.env` 继续保留；不得以删除卷解决配置缺失。

开发配置 `.env.dev` 与 NAS `.env` 分离；开发 Compose 显式使用项目名 `omnirack-replica-dev`，避免与 NAS `omnirack-replica` 复用服务标签。开发 Compose 使用后端 18085、前端 5174、PostgreSQL 15435；Vite 默认代理到 `127.0.0.1:18085`，可用 `API_PROXY_TARGET` 覆盖。宿主机 Go 进程只读取进程环境，不自动加载 `.env`；本机运行时请显式设置 `HTTP_ADDR=127.0.0.1:18085` 和使用 localhost:15435 的 `DATABASE_URL`，Compose 容器内部仍使用 postgres:5432 / backend:8080。

本轮不修改 NAS 三个实例。SMTP、LDAP 外部服务、手机摄像头和全部业务组合不在自动回归覆盖承诺内。
