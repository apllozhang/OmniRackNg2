# 终端与机房设备分开管理

版本：0.2.0-preview.12。

## 入口与档案

- “基础设施 → 机房设备”：默认查询非 终端 分类，继续管理服务器、网络、存储等设备的上架、迁移、下架及 U 位。筛选、分页总数和导出均在对应设备范围内。
- “资产运营 → 终端管理”：只显示 终端 分类，重点管理当前使用人、部门、位置和领用归还。
- “登记 / 编辑 终端 档案”：维护 终端 名称、型号、SN、资产编号等基础信息，类型限定 终端；批量导入使用相同分类限制。没有第二套 终端 档案，旧设备 ID、SN 与二维码保持不变。
- “配置与保修”：按 终端 分类进入原配置页面，维护 CPU、内存、硬盘、系统、保修等。当前使用人及使用中状态须通过领用归还或交接变更，避免只改字段而遗漏交接记录。
- 分类依据设备类型中的 category，不以物理位置判断。一台放在机房的 终端 仍属于 终端。旧 `/devices` 地址保留作为兼容的总台账入口。

## 管理员确认流程

系统管理员、资产管理员可以办理；审计员只能查看、导出。员工不提交申请，不增加审批步骤，不发送额外审批邮件。

| 操作 | 前置条件 | 确认后的台账 |
| --- | --- | --- |
| 领用 | 终端 在库、未报废、未上架、不在设备维修状态 | 使用中，记录接收人、部门、位置和工位 |
| 归还（正常） | 使用中且有使用人 | 在库，清空当前使用人和部门，记录存放位置 |
| 归还（故障） | 使用中且有使用人 | 维修中，清空当前使用人和部门，记录存放位置和故障说明 |
| 换人交接 | 使用中且有使用人；接收人须不同 | 保持使用中，更新使用人、部门、位置和工位 |

每次操作必须填写位置及交接说明；领用、换人交接需填写接收人和部门并确认设备正常。归还时可在说明中登记充电器、鼠标等配件及设备状况。

故障归还后的设备不能直接领用。维修完成后在终端管理点击“维修完成”，记录操作说明和位置后恢复在库，再办理领用；维修和报废统一记录于使用履历。

旧 终端 沿用原使用状态和使用人。没有资产配置的已登记 终端 默认在库，可直接办理首次领用；已有使用中设备可以直接归还或交接。新交接记录会保留首次操作前的原使用人，不补造历史领用记录。

## 记录、导出与一致性

- 交接记录保存设备编码/名称/SN、交接前后状态与使用人/部门/位置、设备状况、说明、确认管理员及服务器确认时间。
- 每台 终端 的“交接记录”分页显示，每页 50 条；“导出此 终端 全部交接记录”会读取全部分页，防止只导出当前页。
- 终端 台账支持按状态、位置、使用人、部门、SN 等筛选；勾选后导出勾选项，没有勾选时导出筛选结果，支持打印原系统二维码。
- 完整业务 JSON 增加 `pcHandovers`，数据库备份自然包含新表。Excel 与业务 JSON 不代替完整数据库备份。
- 设备行锁与版本检查防止多人同时办理。记录、台账和审计在同一事务提交；记录保存失败时全部回滚。重复提交旧版本会提示冲突，须刷新后核对，不能重复领用或归还。
- 不提供交接记录直接编辑、删除入口。确需纠正时通过新的实际业务操作保留痕迹。

## 升级与验证范围

升级沿用旧 `.env` 和原数据库卷，启动时新增 `pc_handovers` 表；不复制或重新编号已有资产，升级前先完成备份。

本次扩展针对 Web 管理端。现有 Android 包没有新增领用归还界面；不要通过旧 App 改写使用中 终端 的使用人，服务器会要求通过交接流程办理。

已使用 SQL mock、状态校验和界面组件测试验证，不等同真实 PostgreSQL 升级与并发验收。本机没有 Docker/PostgreSQL；页面视觉与生产环境流程仍需在测试服务器验收。
