# 位置与备件维护更新：0.2.0-preview.3

preview.16 的三个日常页面、八项录入和辅助设置位置见《备件工作台使用说明》。原引用与历史保护继续保留。

preview.15 日常入口已简化为“入库登记 → 库存台账 → 调拨 → 确认收货”，详见《双渠道审批与备件布局说明》。下文档案和规格引用保护继续有效，历史零库存空档仍可处理。

保留原机柜大屏、LDAP、资产配置、邮件/企微通知与盘点功能，补齐位置、备件规格、备件档案和最低库存规则的编辑、删除入口。本轮没有新增资金字段。

## 区域与资产位置

进入「基础资料 → 区域与资产位置」，每行提供编辑、删除按钮。编辑可修正区域、名称、地址；没有关联业务时也可调整类型及关联机房。办公区自动清空机房关联，避免隐藏字段残留。

有关联资产、备件、库存规则、流水或盘点任务的位置不允许删除，也不允许直接改变类型及机房关联。位置迁移请通过原设备/库存业务流程处理。编辑显示信息不会改写已有盘点快照。

## 机房备件

| 页面 | 编辑内容 | 删除条件 |
| --- | --- | --- |
| 库存明细 | 库位、批次、保修日期；未使用空档还可修正规格、位置、SN | 仅 AVAILABLE、数量为零、无设备安装及在途关联、无流水或盘点引用的空档 |
| 备件规格 | 名称、类别、厂商、型号、料号、具体规格、兼容信息 | 没有备件档案或最低库存规则引用 |
| 最低库存 | 直接编辑当前规则的阈值 | 可删除；对应最低库存提醒同步失效 |
| 机房统计 | 自动根据明细计算 | 修改源档案或办理库存业务后重新汇总 |
| 库存流水 | 保留已完成业务事实 | 不直接编辑、删除，通过后续业务操作更正 |

已有库存或业务历史时，规格、所在位置及 SN 不直接改写，数量和状态通过「办理」变更。已有备件档案的规格不能改变管理方式或计量单位，避免历史数量与 SN 语义失效。

编辑与删除均校验当前版本，过期页面不能覆盖他人修改。系统管理员、资产管理员可操作，审计员只读。删除需界面二次确认；真正未使用的目录记录会移除，删除前完整内容及操作者保留在审计日志中，界面没有撤销删除入口。数据库外键阻止并发产生的关联引用被删断。

## 全新安装

Linux x86_64/amd64，预装 Docker Engine 和 Docker Compose v2；离线包包含三个完整运行镜像，安装时不拉取镜像、不构建源码。

```bash
tar -xzf cabinet-it-assets-offline-0.2.0-preview.3-linux-amd64.tar.gz
cd cabinet-it-assets-offline-0.2.0-preview.3-linux-amd64
bash install.sh
```

访问 http://服务器IP:15173，首次登录信息在本机 .env 中。数据库不发布宿主机端口。

## 升级已有实例：先备份并沿用原配置

项目名仍为 cabinet-it-assets，数据库卷保持原名称。先备份并验证旧实例，在新目录解压后，将**当前正常运行实例的 .env** 以 600 权限复制到新目录，再执行安装。必须保留原 POSTGRES_PASSWORD 和 JWT_SECRET。

```bash
cd /home/inno
tar -xzf cabinet-it-assets-offline-0.2.0-preview.3-linux-amd64.tar.gz
cd cabinet-it-assets-offline-0.2.0-preview.3-linux-amd64
# 将下面路径替换为当前正常运行实例的目录；不要使用曾错误生成的新随机配置。
install -m 600 /home/inno/正常运行的旧版目录/.env .env
bash install.sh
```

如果沿用最初 preview.1 的数据库且没有更改过数据库密码，原 preview.1 的 .env 就是应保留的配置。之前失败目录中新生成的 .env 不能作为升级配置。

本包已内置 installfix1 的升级保护：缺少 .env 且发现已有数据库卷或同项目 PostgreSQL 容器时，立即停止，先复制旧配置再重试，不会重新生成密码。它不会自动猜测旧目录、清库或重置管理员密码。

升级会重新创建本项目应用容器，期间短暂中断；不会导入旧业务数据副本，而是继续使用原数据卷。不要覆盖原安装目录、执行 down -v 或删除数据卷。先在测试环境验证升级与恢复流程。
