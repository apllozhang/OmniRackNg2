# 扫码访问配置（preview.6）

## 设置位置

系统管理员登录 → 左侧“系统设置” → “扫码访问设置”。

“统一扫码访问地址”可填写：

- `https://assets.example.com`：建议使用固定 HTTPS 域名。
- `https://assets.example.com:8443`：非标准 HTTPS 端口。
- `http://203.0.113.10:15173`：示例 IP，只用于说明格式，HTTP 无法满足手机浏览器摄像头的安全上下文要求。
- 留空：沿用生成二维码时浏览器当前访问地址。

填写协议、IP/域名和可选端口，不包含路径、查询参数、账号密码或片段。当前部署在域名根路径，不支持反向代理子目录前缀。

配置保存于 PostgreSQL，由所有操作员共享；仅系统管理员可修改，修改保留审计和版本冲突检查。完整数据库备份包含此配置，不依赖浏览器缓存；JSON 资产导出不是完整数据库备份。

## 生效范围

新打印的设备与备件标签使用保存的地址，并附带原有稳定对象 ID。未成功读取配置时会停止生成，避免意外打印内网地址。

配置页展示按已保存配置生成的扫码查询和扫码盘点入口及入口二维码。扫码查询与盘点页也提供手机入口链接。未保存的输入不影响展示的入口。

二维码仅携带访问地址和对象标识，不携带登录凭据或资产详情；访问后仍需正常登录及相应角色，盘点仍需指定盘点人和有效任务。

## 网络及 HTTPS

统一地址决定链接生成，不会自动打开防火墙、设置 NAT、解析 DNS、安装证书或搭建 VPN。手机只要能访问系统入口即可使用，不必与被盘点设备在同一局域网。

使用公网时，将固定域名解析到实际入口，由有受信任证书的 HTTPS 反向代理转发到原前端 HTTP 服务 15173 端口，页面和 /api/ 都需转发；不要单独发布 PostgreSQL。也可通过企业 VPN 访问内网域名。数据库保持内部网络。

实际切换地址前从手机浏览器验证首页、登录、扫码查询和盘点任务可访问。页面摄像头需要受信任的 HTTPS，裸 HTTP IP 入口可支持手工输入或扫码枪，但不能保证浏览器摄像头可用。系统不绕过证书错误。

建议固定域名配合内外 DNS：办公 Wi-Fi 解析到内部入口，其他已授权网络解析到可达入口，保持标签中的域名不变。修改服务器 IP 时仅调整 DNS/入口，避免重打印。

## 旧标签

已打印二维码的图案不会被配置修改。直接用手机相机打开旧二维码仍访问旧 IP；需要重新打印标签，或者保留旧入口到新域名的访问/跳转路径。

如果旧入口已不可达，可先从可达的新域名登录扫码查询/盘点页，再用页面摄像头扫描旧标签。系统只提取原对象 ID，不请求旧 IP，仍能匹配原设备与备件。不要将扫描识别码当作免登录凭证。

没有网络或入口不可达时仍无法在线提交盘点；本次未增加离线缓存、同步或 App。

## 升级

沿用原项目名 cabinet-it-assets、15173 端口和数据卷。新增 scan_access_settings 配置表，首次启动自动建表，默认配置留空以兼容原行为。升级前备份，复制原正常运行目录的 .env，再执行 bash install.sh。不要删除数据卷，不更改原数据库密码或 JWT_SECRET。

## 验证边界

后端测试覆盖地址格式、配置读取/首次保存/修改/清空、版本冲突、审计失败回滚和角色权限；前端测试覆盖入口链接、新标签地址、配置读取失败、无效地址及旧标签对象匹配。浏览器预览使用虚构只读数据，真实 PostgreSQL 迁移、Docker 启动、实际公网/VPN/DNS 和手机摄像头仍需在测试环境实机验收。
