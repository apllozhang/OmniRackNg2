# 代码、业务与系统评估及风险登记

日期：2026-10-28。范围：0.2.0-preview.16 对照材料、复刻源码、实际注册 API、测试与部署流程。完整性、正确性、安全性和可扩展性分别评价；功能存在不能代替业务正确，测试通过不能证明没有未知缺陷。测试原始结果与最终版本身份以 103 的 `evidence/20261028-hardening/`、发布记录和最新交接为准。

## 评估结论

系统具备继续二次开发的完整应用骨架和主要业务流程，适合先作为内部单组织资产管理系统使用。它是 Vue + Gin + PostgreSQL 的模块化单体，现阶段保持单体比贸然拆微服务更利于维护事务与规则。现有版本不具备成熟企业集成平台的授权粒度、事件交付、迁移治理和容量验证，应按下表完成对应上线门槛后扩大使用范围。

| 方面 | 已有能力 / 可沿用部分 | 主要问题与判断 |
|---|---|---|
| 源码完整性 | 后端、前端、数据库模型、构建、测试、原始材料及 Git 历史；前轮已用 REA 比较路由/应用符号/依赖，补齐原包文档资产 | REA 的符号和字符串对照是完整性证据之一，不证明二进制逐字相同，也不证明所有异常语义一致；新修复须以新版本单独记录 |
| 功能覆盖 | 数据中心/机房/机柜/模板、设备与 U 位、PDU/插座、电源连接、终端领还、库存流转、盘点、扫码、审批、提醒、通知、LDAP 和管理审计 | 主流程较齐全；设备类型、权限、分页、导出和异常恢复需要持续规范；外部 LDAP/SMTP/摄像头未被本轮隔离回归实际覆盖 |
| 业务正确性 | PostgreSQL 事务、软删除、version、U 位数据库排斥约束、专用幂等请求 | 继承代码存在跨模块状态和并发缺陷；本轮已修复下表明确列出的风险，今后新增操作必须同时检查设备位置、电源和资产状态 |
| 安全 | bcrypt、JWT、实时账号/角色检查、同源界面、通知 AES-GCM、审计 | 本轮增强会话撤销、最后管理员保护、限流和资源边界；仍缺细粒度资源隔离、独立机器身份和部署 TLS 等，不能对多租户或互联网直接开放作承诺 |
| 可靠性 | DB 事务与约束、健康检查、审批记录、容器交付 | 本轮补迁移锁、HTTP/DB资源限制和优雅退出；单库单进程仍非高可用，外发通知不具端到端 exactly-once |
| API 与维护性 | 122 个 method/path；handler/service/repository 分层，已有测试 | 活跃 OpenAPI 已重建并从实际源码核验；部分资产 handler 混入 SQL，应逐步收敛到 service，分离输入 DTO 和持久化模型 |
| 扩展性 | UUID、角色、资源 version 和服务分层适合增量改造 | 适合“模块边界 + 明确契约”演进；对接前先做服务身份、scope、external ID、分页/增量读取、事务 outbox，而非让外部系统直接写库 |

未给出笼统“安全95分”等评分：没有统一的业务验收基准、负载目标与生产威胁模型，分数不能支持上线决策。

## 本轮落实的修复

以下均以具体实现和测试为依据；Git 差异提供逐行审查入口。旧登录会话须重新登录，注销会撤销同账号全部会话；密码和权限变更也推进账号版本。这是有意修复的行为变化。

| 编号 | 原问题 / 影响 | 已实施措施 | 主要验证 |
|---|---|---|---|
| F01 | 注销后原 JWT 仍可使用，改密未统一撤销；登录并发保存关联可恢复旧角色 | DB 中 users.version 作为会话版本，每次认证检查实时账号；登录只更新标量字段，避免保存陈旧角色关联 | middleware/service 安全测试；真实 HTTP 改密、注销、停用回归 |
| F02 | 并发移除两个管理员可能使系统失去所有管理员；enabled=false 被 ORM 默认值覆盖 | 管理员变更使用事务 advisory lock 后实时计数；禁用创建状态显式落库 | 仓储测试与真实 PostgreSQL 四种并发变更 |
| F03 | 无登录限速、bcrypt 超长密码别名、生产弱 JWT 配置 | 有界账号/IP进程限流、登录体16KiB、密码8–72 UTF-8字节、HS256与必要claims、生产密钥最低长度和TTL边界 | 配置、模型、处理器、中间件安全测试 |
| F04 | 数据库暂时不可用被当作凭证无效，前端任何刷新失败都注销 | 认证基础设施故障返回503 AUTH_UNAVAILABLE；前端保留凭证并提示重试，401才本地清理 | 后端故障测试；新增前端会话故障测试 |
| F05 | 每次迁移先DROP再建U位排斥约束，失败或并发启动有风险 | DDL事务 + advisory lock，仅缺失时安装且按表限定约束；启动迁移有2分钟上下文 | 重复迁移保留约束OID；并发重叠U位恰好一个提交；SQL失败回滚测试 |
| F06 | PDU连接与设备移动可并发破坏同柜关系，插座状态可脱离连接，输入夹带关联数据 | 统一设备→插座→PDU加锁，验证同柜/有效设备/启用PDU/非负有限功耗；连接时推进插座版本；有电源连接禁止跨柜移动/下架/删除；创建清理系统字段关联 | PDU与设备业务回归、SQL事务测试 |
| F07 | 同一库存幂等键可携不同参数复用，返回旧成功掩盖错误 | 重放时核对主体、库存、动作、数量、目的地、原因等；冲突拒绝 | 库存幂等回归 |
| F08 | 提醒确认与刷新互相覆盖，内容变化保留旧确认 | 行锁及活动状态条件，详情/严重级别变化使旧确认失效 | handler并发与service测试 |
| F09 | LDAP总耗时无界/组查询截断，并发配置覆盖 | 15秒总deadline、取消关闭连接、TLS SNI、解除固定2条组结果上限；配置写入事务锁与version CAS；LDAP角色同步与管理操作共用事务锁，只在角色改变时推进会话版本 | LDAP及仓储/handler测试；真实目录尚未测 |
| F10 | HTTP/DB资源和退出生命周期缺乏边界 | 请求8MiB、128个处理并发、独立4个ready额度、HTTP超时和60秒请求上下文、DB连接池上限20；SIGTERM排空与取消后台任务 | 流式体限制、过载、慢头、readiness隔离、排空/任务取消测试 |
| F11 | 原OpenAPI损坏且遗漏/错写接口 | 保留历史文档，重建OpenAPI 3.0.3与接口/错误码清单；Gin注册表+AST自动检查漂移 | 契约生成/只读check、schema引用、请求体/query/路由回归 |
| F12 | 发布工具存在路径逃逸、锁前读取旧版本、可变配置、失败状态不实 | 新发布控制器严格版本ID、摘要与拓扑检查，先锁后读取，不可变环境快照/镜像ID，明确应用回滚兼容条件，诚实记录失败 | 正常Python和-O的发布工具测试；真实部署记录另列 |
| F13 | 老依赖与旧编译器可能继承已知漏洞，诊断入口夹在应用根 | 用官方Go1.27.3工具链，按govulncheck结果定向升级依赖；旧硬编码数据库诊断脚本移到历史文本 | 新依赖完整Go与真实DB回归；漏洞扫描原始输出 |
| F14 | 工作与证据分散在本地、旧部署目录、聊天记录 | 103权威Git/worktree/任务/证据/交接目录；脚本自动保存实际Git状态、差异与非秘密未跟踪文件 | 工作区脚本真实临时Git测试、103接手演练 |

限流是每进程的；反向代理后的所有访问可能共享后端观察到的IP，账号维度仍生效。请求上下文要求调用链配合取消，并不强制停止任意CPU循环。流式请求超过限制时部分handler会返回400绑定错误，不能宣传所有超限都返回413。兼容业务导入超过8MiB时需要分批或另行设计异步导入，不得无上限放开。

## 对接业务系统的推荐落地顺序

1. 先确定外部系统主数据归属、业务动作和身份/资源范围，不把数据库表直接暴露为公共写接口。
2. 为选定用例增加服务账号、scope、externalSystem/externalId唯一映射和审计主体；写入继续经过同一service规则。
3. 在现有 `/api/v1` 之上提供明确输入DTO、稳定分页与错误码、请求ID、版本冲突和幂等语义；保留兼容窗口。
4. 用事务outbox发布业务事件，webhook签名/时间窗/重放防护/重试/死信；敏感字段默认不出站。
5. 以“事件重复、乱序、超时、并发改动、对方系统不可用”为验收场景；再考虑读模型/独立worker和水平扩展。
