# 台账分工与终端使用状态

版本：0.2.0-preview.12。

## 为什么多处能看到同一资产

终端管理、机房设备、配置与保修中心都读取同一设备档案，以同一个设备 ID 关联，不是各建一套资产。原界面入口容易造成重复台账的印象，因此本次明确分工：

| 入口 | 用途 |
| --- | --- |
| 终端管理 | 登记终端、维护基础档案，办理领用/归还/交接/维修/报废，查看使用履历 |
| 机房设备 | 登记服务器、网络等设备，管理上架/迁移/下架及 U 位 |
| 配置与保修中心 | 汇总上述同一批设备的配置、位置与保修；维护 CPU/内存等扩展配置、保修和维保。提醒、公共位置、审计和完整导出备份已迁至独立入口，见《导航与功能分工说明》 |

配置中心取消泛化的“登记设备资产”和重复台账按钮；终端、机房设备分别从左侧对应台账进入。旧页面地址保留。不要把已存在的设备再次新增；配置中心的修改会在同一档案的其他视图展示。

## 终端状态

终端新增表单显示“使用状态”，不再显示待上架、待下架等机柜词语，并隐藏 U 高度和双路电源。四种状态为：

| 状态 | 说明与后续操作 |
| --- | --- |
| 在库 | 可领用、登记维修或报废 |
| 使用中 | 必须有使用人、部门和位置；可归还或换人交接，不能直接报废 |
| 维修中 | 可确认维修完成恢复在库，或确认报废 |
| 已报废 | 保留档案与历史，不再领用或恢复使用 |

正常归还进入在库，故障归还进入维修中。维修、维修完成和报废均需要管理员确认、存放位置和操作说明，并写入使用履历。重复提交或他人先修改会提示版本冲突，需刷新核对。

编辑基础档案时只展示领用台账的实际状态，不能直接修改下拉框绕过流程。配置中心也不能直接改终端状态、当前使用人和使用部门；状态变化统一通过终端管理办理，避免一处显示在库、另一处显示使用中。

## 初始登记

可以直接登记在库、使用中、维修中或已报废的存量终端。选择使用中时，必须填写使用人、部门和位置。

档案、初始配置、初始化履历与审计一起提交；保存失败时全部回滚，不会留下只建了一半的设备。初始化记录只说明本次确认的当前状态，不补造过去领用日期，也不假设做过设备验收。

批量新增支持在库、维修中和已报废，会使用同一原子登记接口；使用中设备请逐件登记使用人和位置。批量更新已有终端基础信息时，清空使用状态列；状态变更请走业务操作。机房设备仍沿用原模板和生命周期。

## 导出与兼容

- 终端台账、配置中心、终端档案回显和设备 Excel 导出读取实际终端使用状态。终端没有机柜位置时，导出中的上架状态、双路电源标为不适用，U 高度留空。
- 初始登记、领用、归还、交接、维修、维修完成、报废可在“使用履历”查看并完整导出；完整业务 JSON 与数据库备份继续包含这些记录。
- 旧设备 ID、二维码、SN 与既有记录保留。底层兼容的机柜生命周期字段仍存在，终端业务状态以资产配置/领用台账为准；旧报废、维护标志在读取时兼容处理，不复制设备档案。
- 有旧机柜绑定的终端须先核实并通过机柜流程下架，再办理终端业务，避免直接丢弃既有 U 位记录。

升级沿用原 `.env` 与数据卷。当前验证为代码测试、SQL mock、前后端构建和安装脚本模拟，不等同真实 PostgreSQL 保存点/事务、升级和并发验收；应先在测试服务器验证。此次为 Web 管理端扩展，Android APK 没有重新打包。
