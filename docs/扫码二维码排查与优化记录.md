# 扫码与二维码排查记录（preview.8）

## 本轮修复

| 问题 | 调整后的行为 |
|---|---|
| 系统二维码只提取 UUID，丢失设备/备件类型 | 保留 device/stock 类型，并使用规范 UUID 校验；系统链接只按对应对象 ID 定位，不回退匹配其他设备的 SN 或外部标签。 |
| 同时携带 device/stock 或重复 device 参数时取第一项 | 不当作有效系统码解析；未明确绑定的异常内容不能定位记录。 |
| 较慢的旧查询覆盖新查询、空输入残留旧结果 | 仅最后一次请求可更新结果；输入清空、路由切回普通扫码入口或离开页面时，使旧请求失效。 |
| 切换任务时仍展示旧明细、可能用新任务名识别旧行 | 清空旧明细并显示加载状态，仅接受当前任务的明细响应；加载失败不启用扫描。 |
| 确认盘点期间仍可扫码或切换任务 | 确认时停止相机，暂时禁用任务切换；确认提交绑定打开时的任务，重复点击不重复发请求。 |
| 摄像头取消、解码器启动失败、后台切换后可能仍占用 | 显式持有并停止 MediaStream，释放解码器；处理延迟权限结果，旧解码器释放结束后再允许新启动。 |
| 手机权限、占用错误提示不明确 | 对权限拒绝、未找到相机、设备占用给出中文提示；保持扫码枪与手工输入可用。 |
| 请求与二维码生成结束后才 window.open | 在用户点击时同步预留标签窗口；配置、详情或生成失败时关闭窗口，拦截/主动关闭均有提示。单设备编辑打印在预留窗口之后重读已保存数据。 |
| 标签二维码留白小、源图分辨率偏低、长名称易溢出 | 增加 4 模块留白；打印源图 360px、纠错 M，长名称换行并显示 SN；预览和入口码同样增加留白。 |
| 前端允许保存端口 0 或空端口，后端拒绝 | 前端先行阻止，避免无效配置提交。 |
| 把平台自己的系统码当外部标签重新绑定 | 扫描绑定时提示系统码无需重复绑定，防止字段含义混淆。 |

## 保持的行为

系统二维码依旧由统一扫码访问地址和稳定对象 ID 生成，旧域名/IP 的有效标签仍可在当前平台扫码页面识别。外部编码/链接按原始内容精确匹配，不请求外部网站；重复原始识别码仍提示歧义。盘点沿用创建时快照、指定盘点人、现场确认及差异复核流程，不由扫码直接修改台账。没有新增离线缓存、App、自动网络发现或公网服务。

本轮仅调整前端扫码及打印链路，不更改数据库结构、数据卷或认证规则。扫码查询仍使用现有台账接口；未改造为新的服务器端检索服务。

## 回归验证

自动测试覆盖：类型区分、跨字段误匹配、旧域名/大写 UUID、重复及无效参数；外部标签、快照与歧义；查询/任务乱序响应、清空输入、失败加载；确认暂停扫描、固定任务提交和重复提交；相机权限延迟、解码失败、重复回调、后台释放及关闭/重启；标签窗口预留、弹窗拦截、配置失败、主动关窗、最新字段与 HTML 转义。完整前端类型检查和生产构建在交付前执行。

浏览器验证使用明确标记的虚构数据。实图二维码经解码回读确认目标地址与对象 ID。真实手机摄像头/打印机、HTTPS 证书、公网或 VPN、真实 Docker/PostgreSQL 启动仍需在部署环境验收，不把模拟测试当作生产环境验证。

## 升级

使用完整离线包 cabinet-it-assets-offline-0.2.0-preview.8-linux-amd64.tar.gz。

先备份并找回原正常运行版本的 .env，再复制到新目录执行 bash install.sh；不要把新目录自身当 OLD_DIR。缺少原配置时安装器会保留数据并停止，本版不会猜测原密码或重建数据卷。可先用下面命令只查找路径：

```bash
find /home/inno -maxdepth 4 -type f -name .env -path '*/cabinet-it-assets-*/*' -print
```

保留原项目名 cabinet-it-assets、数据库密码、JWT_SECRET、数据卷及原端口。离线包仍要求服务器已具备 Docker Engine 与 Compose v2。
