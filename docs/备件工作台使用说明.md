# 机房备件工作台（preview.16）

## 日常使用只看三个页面

| 入口 | 作用 |
|---|---|
| 库存明细 | 按区域、类型、名称/型号/SN/备注、位置和状态查询；查看八项主字段 |
| 机房统计 | 按区域、具体位置及型号资料合计可用、预留、待检测、故障、在途、维修中数量 |
| 库存流水 | 查看操作事由、数量变化、状态变化及来源/目标位置，支持导出 |

“备件规格”和“最低库存”迁至右上角“资料与预警设置”。它们是辅助维护功能，不是录入的前置步骤。规格可补充兼容信息和料号；最低库存按具体位置及型号设置。

## 先录入，再查看详情

1. 点击右上角“录入备件”。默认直接填写区域/存放位置、类型、名称、型号、数量、序列号、备注、状态。
2. 区域通过既有资产位置选择，并保留具体库房，避免同城多库混淆。如没有位置，先在“基础资料 → 区域与资产位置”登记。
3. 类型和名称必填，型号和备注按实际补充。一个 SN 对应一件；无 SN 的物料按数量管理。已有型号可以点击“从已有型号带入”，不是必选步骤。
4. 初始状态可选“可用、待检测、故障、维修中”。库存及初始流水在同一事务保存，故障/维修中的数量不会计入可用库存。不能通过初始录入直接登记在途、已安装、已报废或已预留，它们需要有实际业务依据及关联对象。
5. 保存后在库存明细中查看；每行“详情”集中展示八项主字段、规格、库位、批次、保障信息及该备件流水。

同类型/名称/型号和管理方式的自动资料复用；不与已有不同料号的详细资料擅自合并。首次登记生成 AUTO-SPARE 管理编码，规格与详细兼容信息可后续维护。

## 日常操作

- 常用行操作只显示“详情、调拨/确认收货、更多”。“更多”包含编辑档案、补充入库、领用/安装、预留、检测/故障、维修、报废等当前状态允许的操作。
- 有库存和历史时，数量/状态通过库存操作变化，不直接改档案；区域和 SN 继续受原引用保护。完整历史不能直接改写或删除。
- 调拨发出后不算可用，目标位置确认收货后才算可用。按 SN 物料保留来源位置直至收货，详情可看调拨目标。
- 例如数量管理备件：上海入库 10 件，调拨 3 件到杭州；上海可用 7 件、杭州在途 3 件。杭州确认收货后，在途归零、可用为 3 件。
- 故障、维修、报废等状态切换仍按当前库存行整批办理，并明确提示数量。维修完成通过检测合格恢复可用。

## 看流水

新流水同时保留数量和状态前后值，以及来源位置/调拨目标。在接收方数量批次详情中，调拨创建显示“0 → 调拨数量”和“新增调拨批次 → 在途”，不是来源库存的扣减；全局流水保留原来源记录变化。

历史流水没有保存过的状态显示“未记录”，不根据当前状态倒推。初始录入可从零库存变为指定状态，并记录实际数量，不补造此前维修或入库时间。旧客户端省略初始状态仍按可用处理，重试不能改变初始登记状态或重复增加数量。

## 升级

新增 `spare_movements.before_state` 和 `after_state` 两个字段，由现有 AutoMigrate 创建，不回填历史状态，不清空库存、规格、预警或流水。保留旧 API、二维码、业务导出及双渠道审批通知。

升级前备份，复制旧有效安装目录 `.env` 到新目录并保持权限 600，沿用原 JWT_SECRET 和数据库卷；执行 `bash install.sh`。不要删除数据卷或重新生成密码。

本机回归使用模拟数据库与组件测试，未做真实 Docker/PostgreSQL 升级、真实消息投递或浏览器视觉验收；Android APK 未重打。
